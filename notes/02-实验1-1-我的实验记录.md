###### 五组结果对比

| 配置 | 模型轮数 | 实际工具调用 | 完全相同的重复调用 | 有终止回答 | 完成营收任务 | 本次实际结果 |
|---|---:|---:|---:|---|---|---|
| `full`：完整上下文 | 3 | 4 | 0 | 是 | 是 | 换汇、汇总后正确回答 |
| `no_history`：不传历史 | 5 | 15 | 12 | 否 | 否 | 每轮重新换汇，到达轮数上限 |
| `no_reasoning`：不保留历史推理 | 4 | 5 | 0 | 是 | 是 | 保留工具结果，仍然正确计算 |
| `no_tool_calls`：不提供工具定义 | 1 | 0 | 0 | 是 | 否 | 输出类似工具调用的文本，没有执行工具 |
| `no_tool_results`：隐藏工具结果 | 5 | 10 | 3 | 是 | 否 | 重试和测试后说明缺少数据，拒绝给出金额 |

一轮是一次模型请求；同一轮可以请求多个工具，所以 5 轮可能产生 15 次工具调用。这里的重复次数按“工具名称和参数完全相同”计算，改大小写或改测试金额的尝试可能不计为相同调用。

**full：完整上下文，任务成功**

第 1 轮同时请求三次 `convert_currency`，将欧元、英镑和日元营收转换成美元。工具实际返回：

| 季度        |         美元金额 |
| --------- | -----------: |
| Q1：原本就是美元 | 2,500,000.00 |
| Q2：欧元换美元  | 2,282,608.70 |
| Q3：英镑换美元  | 2,278,481.01 |
| Q4：日元换美元  | 2,541,806.02 |

第 2 轮，模型能看到这三次工具结果，调用一次 `code_interpreter` 求和并除以 4。工具返回全年总额 **9,602,895.73 美元**、季度平均 **2,400,723.93 美元**。第 3 轮，模型读到汇总结果并给出正确回答。

这个过程是完整反馈循环：模型请求行动 → 工具执行 → Harness 将结果放进下一轮上下文 → 模型继续决策。四次工具调用都没有重复。

**no_history：工具能运行，但模型每轮都从头开始**

每轮实际发送的消息角色都只有 `system` 和 `user`，工具定义仍然存在，但之前的模型回复、工具调用记录和工具结果都不再发送。

本地工具每次都完成了换汇。可是下一轮模型看不到这些进度，于是五轮都请求同样的三次换汇：共 15 次调用，其中 12 次是完全相同的重复调用。它没有推进到全年汇总，也没有最终回答，直到达到 5 轮上限。

这组说明：工具执行成功，并不意味着下一轮模型知道任务已经推进。缺少历史会让本次 Agent 反复重做相同步骤。

**no_reasoning：移除历史推理后，本次仍然算对**

这个配置移除的是历史模型消息中的 `reasoning_content`，并没有关闭模型当前轮的推理。证据中，每轮仍产生新的推理内容；历史工具调用和实际结果也仍然保留。

第 1 轮完成三次换汇；第 2 轮用 `calculate` 算全年总额；第 3 轮再用 `calculate` 除以 4；第 4 轮正确回答。总额和平均值与 `full` 一致。

它比 `full` 多一轮模型请求和一次工具调用，但两组采用了不同的汇总方式，单次运行不能把这个差异完全归因于不保留历史推理。本次没有观察到答案正确性下降，也没有观察到“决策不连贯”。一种可能解释是：这道题的后续步骤可以直接根据保留的工具结果重新判断。

**no_tool_calls：写出了调用样子的文本，实际没有工具调用**

该组请求没有提供 `tools` 定义。模型在普通回复 `content` 中输出了包含 `DSML`、`invoke name="currency_conversion"` 等标记的文本，看起来像要请求换汇，但响应没有结构化的 `tool_calls`，本地执行记录也确实是 0 次调用。

Harness 将没有结构化工具调用的回复当作终止文本，因此 `completed=true`。不过它既没有实际换汇，也没有给出全年总额和季度平均值，`task_success=false`。

结果标签 `no_unsupported_numbers` 仅表示检查器没有检测到无依据的营收金额，不能把它理解为“任务完成”或“模型明确拒绝回答”。本次实际行为是输出了一段没有被执行的调用文本。

核心区别：**模型说自己要调用工具，和 Harness 确实执行了工具，是两件事。** 要看结构化响应和实际执行记录。

**no_tool_results：记得自己调用过，但看不到结果**
该组保留历史调用记录和历史推理，本地工具也正常返回换汇数据；但 Harness 发给模型的 `tool` 消息内容全部被置空。因此原始证据里能看到工具结果，模型实际收到的请求里却看不到。

实际过程为：第 1 轮做三次换汇；第 2 轮重复这三次；第 3 轮尝试小金额和美元换美元的测试；第 4 轮尝试更换币种代码大小写；第 5 轮给出终止回答，说明缺少可观察的换汇数据，遵守“不得自行估计汇率”的要求，拒绝提供总额和平均值。

共 10 次工具调用，其中 3 次完全相同的重复调用。这次有终止回答，不能写成“耗尽轮数仍没有回答”；但它没有完成营收任务。模型认为工具没有返回数据，从执行记录看，原因实际是结果被 Harness 隐藏了，而不是换汇工具坏了。
### evidence.json 中几个字段怎么读

- `iterations`：模型请求轮数；
- `tool_calls`：实际工具执行记录；
- `repeated_tool_calls`：相同工具与参数的重复次数。
- `completed`：是否出现终止文本回答；它不是“任务是否做对”。
- `task_success`：是否满足本题的标准答案检查。
- `error`：五组都为 `null`，这次没有 API 报错。达到轮数上限或未完成任务，不一定表现为异常。
- `context_contract.passed`：实际请求是否符合该组消融配置。五组都是 `true`，说明本次比较确实按配置改变了上下文。
- `analysis.experiment_execution_accepted=true`：官方五组齐全、配置检查通过、存在真实 API 证据且完整基线答对；不是五组全部答对。
- `analysis.manuscript_behavior_claims.without_reasoning_degraded=false`：本次没有观察到移除历史推理导致答案正确性下降。因此 `all_manuscript_behavior_claims_observed=false`，这不是实验执行失败。
- `groundedness.verdict`：本次正确组为 `not_assessable`，不能单靠它声称自动检查已证明所有表述都有依据。我另行对照了工具返回金额、汇总输出和最终答案，确认这两个目标金额一致。标准答案检查也不等于审核全部自然语言内容。

需要进一步读轨迹时，先看各组 `api_turns[].request.messages` 中模型实际收到什么，再看 `response` 和 `tool_calls` 中它请求并执行了什么，最后对照 `final_answer`。不要只看最后一句答案。

***结论：Agent 的表现不只由模型决定。相同模型面对相同任务，Harness 是否保留历史、提供工具定义、回传工具结果，会影响任务能否继续推进。模型必须看到行动结果，才能据此决定下一步；工具已经执行和模型已经知道结果不能画等号***。
