# Task2：用户记忆与 RAG 学习笔记

Task2 对应 Chapter 3「用户记忆和知识库」。本阶段主要学习两类能力：Agent 如何保存、更新和调用长期用户信息；RAG 如何从外部资料中检索相关内容，再把检索结果放入模型上下文。

## RAG 的基本流程

```text
文档 → 分块与索引
用户问题 → 检索相关片段 → 放入上下文 → 模型生成回答
```

检索阶段决定模型能看到哪些外部资料。模型只能基于收到的上下文回答，因此检索遗漏、排序错误和过期资料都会影响后续结果。

## BM25 稀疏检索实验

### 项目目的

课程的 `chapter3/sparse-embedding` 项目实现了一个教学型 BM25 搜索引擎。它把文档拆成词并建立倒排索引；收到查询后，先找到含查询词的候选文档，再使用 BM25 计算相关性得分和排序。

该实验不调用大模型，重点观察两点：

1. BM25 为什么适合错误码、产品编号和专有名词等精确检索。
2. BM25 为什么可能漏掉只使用同义词表达的相关文档。

### 核心代码与流程

- `cli.py`：接收查询、返回数量、解释模式和输出路径。
- `bm25_engine.py`：实现分词、倒排索引、BM25 打分和排序。

```text
CLI 接收查询
  → 对查询和文档分词
  → 建立“词 → 文档”倒排索引
  → 找到至少命中一个查询词的候选文档
  → 计算 BM25 得分
  → 按得分返回 top-k
```

### 主要参数

| 参数 | 作用 | 本次设置 |
| --- | --- | --- |
| `query` | 要检索的关键词 | `model distillation`、`cat` 等 |
| `top_k` | 最多返回多少篇文档 | `5` |
| `k1` | 控制词频贡献的饱和速度 | `1.5` |
| `b` | 控制文档长度归一化强度 | `0.75` |
| `--explain` | 展示查询词的 TF、IDF 和得分贡献 | 开启 |
| `--output` | 保存结构化 JSON | 开启 |

TF 表示词在文档中出现的次数；IDF 表示词在整个集合中是否稀有。BM25 综合词频、稀有程度和文档长度计算相关性。

### 本人运行结果

本次亲自运行了三组 BM25 实验，保留结构化 JSON：

1. 查询 `model distillation`，成功召回 `doc_3` 和 `doc_4`；`doc_3` 得分更高，排在第一。
2. 查询 `cat`，没有召回只包含 `kitten` 和 `feline` 的相关文档，暴露了同义词漏召回问题。
3. 五个标注查询的宏平均 Recall@5 为 `0.800`、Precision@5 为 `0.700`、MRR 为 `0.800`。

## 混合检索与重排

课程中的混合检索流水线可以概括为：

```text
分块 → BM25 与 Dense 两路召回 → RRF/Weighted 融合 → Cross-Encoder 重排
```

- BM25 擅长精确词项、编号和错误码。
- Dense 通过向量相似度处理语义相近但词面不同的表达。
- RRF 不直接相加两种检索器的原始分数，而是根据各路排名累加贡献。
- Reranker 只能重排已经召回的候选，不能找回前面遗漏的文档。

RRF 的基本形式为：

```text
RRF(document) = Σ 1 / (k + rank)
```

## 用户长期记忆

保存全部聊天历史，不等于拥有有效长期记忆。课程项目把即时对话与后台记忆处理分开：

```text
原始对话
  → 保存聊天历史
  → 后台分析哪些信息值得长期保留
  → add / update / delete
  → 持久化记忆
  → 新会话按需读取
```

核心职责：

- `ConversationalAgent.chat()`：读取记忆、回答并保存原始对话。
- `BackgroundMemoryProcessor.process_recent_conversations()`：分析尚未处理的对话。
- `UserMemoryAgent.execute_task()`：让模型决定使用哪个记忆工具及其参数。
- `MemoryManager`：执行新增、更新、删除和持久化。

聊天历史是原始材料；长期记忆是经过筛选、更新和冲突处理的状态。验证长期记忆是否生效，不能只看最终回答，还应检查工具调用、持久化文件和新会话是否实际使用更新后的信息。

## 学习结论

这次学习让我理解，RAG 的关键不只是“接一个知识库”，而是把文档处理、检索、排序和上下文组织连成可验证的链路。BM25 对精确词项很有效，但 `cat` 查询无法召回只包含 `kitten`、`feline` 的文档，说明单一关键词检索存在明显边界。混合检索可以让词项匹配与语义召回互补，但融合和重排仍需用真实查询集评测。用户记忆也不是简单保存聊天记录，而是由模型判断需要新增、更新或删除的信息，再由 Harness 执行并持久化。实验结果必须以本人真实运行产生的原始文件为准。
