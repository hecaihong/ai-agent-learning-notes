## 本章解决什么问题

把模型的决策连接到真实程序、文件、数据库、API 和其他 Agent，同时控制参数、权限、错误和副作用。

## 我的问题与困惑

### 每个 Python `def` 都是一个小模型吗？

不是。`def` 定义的是普通 Python 函数。只有把函数实现、模型可见的 Schema 和 Harness 执行映射连接起来，它才成为模型可调用的工具。

### 函数必须写说明吗？

Python docstring 不是强制语法，但模型必须获得清楚的工具描述和参数 Schema。框架可以从 docstring 生成说明，也可以单独维护 Schema。

### 只有一个 EXE，也能做 MCP 吗？

可以，不需要 EXE 源码。前提是能确定它的输入、启动方式和可观察输出。MCP Server 在外部校验参数、启动 EXE、读取结果并返回结构化响应。

### MCP 做得好坏由什么控制？

工具名称和描述、参数约束、执行正确性、错误处理、权限、输出结构、日志审计和带模型的任务评测共同决定质量。

### MCP 和工具是什么关系？

工具是具体能力；MCP 是暴露工具、资源和提示模板的标准协议。MCP 统一连接方式，但不会自动保证工具正确或安全。

## 五类工具

- 感知：搜索、读文件、查询数据库。
- 执行：写文件、运行代码、调用业务操作。
- 协作：创建 Agent、传递任务、请求人工处理。
- 用户沟通：通知、表单、聊天和语音。
- 事件触发：定时器、消息队列和系统告警。

## 怎么在实践中落地

```text
工具实现
→ 清楚的名称、描述和参数 Schema
→ MCP Server 注册
→ MCP Client tools/list 发现
→ 模型决定工具和参数
→ Harness tools/call 受控执行
→ 结构化结果返回模型
```

高风险工具必须限制路径和参数，设置超时与审批，并检查真实副作用。不能只看 `success=true` 或最终文字。
