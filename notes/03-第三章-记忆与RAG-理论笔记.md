## 本章解决什么问题

让 Agent 在会话结束后仍能使用重要用户信息，并从外部资料中检索当前任务需要的知识。

## 我的问题与困惑

### 保存聊天记录等于拥有记忆吗？

不等于。聊天记录是原始轨迹；长期记忆是经过选择、合并、更新和淘汰后的稳定信息。

### Memory、Context 和 RAG 是什么关系？

- Memory：跨会话保存的信息。
- RAG：从记忆或知识库中找出相关内容。
- Context：把检索结果与当前任务一起交给模型。

### RAG 的核心流程是什么？

```text
文档清洗与分块
→ 建立索引
→ 根据问题召回候选
→ 融合与重排
→ 相关片段进入 Context
→ 模型基于证据回答
```

### BM25、Dense 和混合检索怎么选？

- BM25：擅长编号、错误码、专有名词和精确词面。
- Dense：擅长同义表达和语义相似。
- Hybrid：合并两路候选，再进行重排。

### Reranker 能补回漏掉的文档吗？

不能。Reranker 只能重新排列召回阶段已经找到的候选。

### 文档为什么要分块？

块太大会混入无关信息，块太小会切断代词、时间和上下游关系。分块参数必须用真实查询集评测。

## 怎么在实践中落地

用户稳定偏好写入长期记忆；企业制度和产品资料进入知识库。每次任务先检索，再把少量高相关、有来源、有版本的内容放入 Context。

评估时不能只看最终回答，还要检查召回结果、排序、来源、版本和回答是否忠实使用证据。
