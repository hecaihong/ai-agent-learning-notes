## 实验一：把 Python 函数注册成工具

### 我的操作

1. 编写 `summarize_revenue()`。
2. 增加模型可见的名称、说明和参数 Schema。
3. 在执行映射中连接工具名与 Python 函数。
4. 测试正常参数、非法金额和数值溢出。

### 实际结果与分析

3 个本地测试通过，说明函数、说明和执行映射已经接通。新增工具是否被真实模型自主选择尚未验证，因此不能只凭最终金额正确声称模型调用成功。

### 实验结论

```text
函数实现 + 工具 Schema + 执行映射 = 可被 Harness 执行的模型工具
```

## 实验三：MCP 协议冒烟测试

> 运行状态：助手真实运行；本人复跑与截图待完成。

### 要验证什么

验证 `stdio` 连接、协议握手、`tools/list` 和 `tools/call`，而不是直接调用 Python 函数。

### 实际结果

| 检查 | 结果 |
|---|---|
| MCP SDK | 2.3.0 |
| 协议版本 | 2026-07-28 |
| Server | `perception-tools` |
| `tools/list` | 返回 127 个工具，包含 `file_reader` |
| `tools/call` | `is_error=false`，成功读取本地文件 |

### 结果分析

`tools/list` 只负责发现；`tools/call` 才触发执行。Server 能启动不等于 MCP 链路跑通，至少还要完成握手、发现和一次真实调用。

## 实验四：Perception Tools 离线演示

> 运行状态：助手真实运行；本人复跑与截图待完成。

### 我的操作

离线执行 `grep_search`、`read_file` 和 `search_knowledge_base`，跳过联网和授权工具。

### 实际结果

| 工具 | 结果 | 分析 |
|---|---|---|
| `grep` | 返回 5 条，`truncated=true` | 达到返回上限，不代表总量只有 5 条 |
| `file_reader` | 原文件 4840 字节，只返回前 200 字符 | 限制的是进入上下文的内容，原文件未修改 |
| 知识库检索 | 命中 1 个文件 | `top_k=3` 是上限，不保证返回 3 个 |

### 实验结论

统一的 `success / message / metadata` 让 Harness 能识别成功、空结果、执行范围和截断状态。本实验调用顺序由代码写死，没有证明模型能够自主选择工具。
