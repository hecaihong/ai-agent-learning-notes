## 3. Glossary：先评“是不是术语”，再评“译得对不对”

重新查看正式术语表，`T024 theater air`、`T033 major c2`、`T040 below the theater air` 等带有明显截断或短语片段特征，需要回原文核对边界。`T006 Assessment / T011 Assessing`、`T050 Coordination / T051 Coordinating`、`T016 TAC C2 / T078 Tactical C2` 应检查能否合并为概念条目并保留别名；这些例子不意味着所有近似词形都应无条件合并。

原文出现的 `DIRLAUTH`、`OPCON`、`CCMD`、`JFC`、`MTO` 和 `OE` 没有对应的正式英文术语条目。其缺失提示候选生成和筛选均需要复核；不能只因为一个缩写低频就忽略它，也不能直接把这六项当作整章完整的标准答案。

原笔记写过“召回高但精度低”。目前缺少完整金标准，只能支持“覆盖条目增加，同时观察到误收与漏收”，无法给出召回率高低的定量结论。

建议按归一后的概念及其别名建立人工标准表，再计算：

- 收录精确率 = 正确收录的领域概念数 / 全部收录概念数。
- 术语召回率 = 正确收录的领域概念数 / 原文应收录的领域概念总数。标准表须独立阅读全文建立，不能只在 88 个候选里选答案，否则候选生成阶段的漏项会被掩盖。
- 译名正确率 = 译名正确的有效术语数 / 已检查的有效术语数。误收词不混入这个分母。
- 证据有效率 = 原文依据确实支持收录的条目数 / 已检查的收录条目数。非空字段不等于有效证据。

上述语义比例本次均未计算。标准表需要记录概念边界、允许译法、原文位置、判定理由和待确认项。

## 4. Translation 与 Revision：12 个位置的前后对照

修订是 Translation Agent 的再次调用，本实验共有四类角色，不能因为多了一个修订阶段就称为第五种独立 Agent。

| 编号 / 块 | 关注位置 | 初稿与修订对照 | 本次判断 |
|---|---|---|---|
| S01 / 01 | 开头列举四项主要 C2 活动 | 初稿和修订均保留计划、准备、执行、评估 | 此处四项枚举保留 |
| S02 / 01 | 计划活动包含设计，以及设计与计划的关系 | 两稿均保留这些关系 | 此处关键关系保留 |
| S03 / 01 | 将空中力量原则适配作战环境 | 从“将……针对……进行裁剪”改成“根据……裁剪” | 对应搭配得到改善 |
| S04 / 02 | C2 Nodes 中被插入框打断的句子 | 修订合并段落后仍为“跨越多个梯次作战行动” | 格式修复后含义仍不清；需先恢复原文连续句 |
| S05 / 02 | DIRLAUTH 段落 | 修订新增 `[待审]` | 保留了不确定性，但交付待确认项没有解决 |
| S06 / 02 | 英文 `MTO technique` | 两稿均变成“任务式指挥技术”，未保留 MTO | 原缩写对应关系不可直接回溯；需要术语核对 |
| S07 / 03 | 定期或事件触发评估的条目 | “进行评做”改为“开展评估” | 已修复错字 |
| S08 / 03 | `accompanying plans` 所在句 | 初稿为“伴随计划”，修订为 `accompanying 计划` | 新增未译英文，属于回归问题 |
| S09 / 03 | MOP/MOE 的两类问题 | 两稿均区分“正确地做事”与“做正确的事” | 此处两类问题得到保留；不据此认可全部译名 |
| S10 / 04 | 开头 `subordinate commander` | 初稿中英混排，修订改为“下级指挥官” | 该处英文残留已清理 |
| S11 / 04 | 指挥关系段中的 OPCON | 修订补入中文解释并保留缩写 | 缩写可读性改善；正式术语库未同步更新 |
| S12 / 04 | 脚注 9 | 原文有说明正文，两稿均只有上标 `⁹` | 漏译仍存在；保留脚注编号不等于保留脚注内容 |

S04 的连续英文应为 `Nodes may span several levels of operations and have varying levels of capability.`，需移开插入框后再解释。这里暴露了输入文本重建与翻译两个阶段的问题，不能把全部责任归给翻译提示词。

后续正式评测应先对齐原文句段，再标注漏译、增译、误译、数字、否定和条件的变化。可报告“每千英文词已确认错误数”，同时保留错误严重程度；不把中英字符长度比直接叫作信息保留率。

修订评价至少记录：旧问题修复率 = 已确认修复的旧问题数 / 本轮要求修复且已确认的旧问题数；同时统计新增问题数、残留问题数及严重程度。新增问题应检查整个改动范围，不能只检查原有问题位置。本表不用于计算全章修复率或净质量提升。

## 5. Proofreading：报告里的每条“问题”也要接受检查

报告第 6 条称相关译法“使用一致，无问题”，第 7 条称两个不同术语“使用正确”，却都被放进 `issues`。第 10 条声称短语缺少“的”，给出的一个建议又重复原短语。这些记录足以说明审校问题清单混入了无问题说明、提醒和不清楚的修改建议。

第 15 条发现了跨页断句，却给出了“多个梯次作战行动”的错误重组建议。报告发现错字与英文残留有用，但“发现问题”和“提出正确修法”需要分别评价。此次审校请求只有中文初稿与术语表，没有英文正文，无法承担完整的英中忠实度核查。

建议以后把输出分为“确认缺陷、风格建议、待核实”，每条附原文位置、译文位置、原因和建议。建立独立问题清单后，再计算问题精确率 TP/(TP+FP) 和召回率 TP/(TP+FN)。其中 TP 为报告正确发现的问题，FP 为误报，FN 为独立复核发现而报告漏掉的问题；同一问题重复报告只匹配一次，额外重复项另报数量。风格建议单列，待核实项须先裁定再纳入统计，并报告尚未裁定的数量。经裁定的缺陷报告中，误报比例为 FP/(TP+FP)，与统计分类中通常使用的假阳性率 FP/(FP+TN) 不是同一个分母。

本次没有完整独立问题清单，因此不能给出审校总体精确率、召回率或误报率。上述两条“使用正确”的例子也不能自动代表其余 34 条都正确。

## 6. Manager 与系统：决策需要落到可检查的产物

Manager 依据报告选择四块返修，实际也发生了四次修订，能证明调度链路执行完成。但报告可能误报或漏报，Manager 与报告一致只能算路由一致性。它还要求同步补充术语表，却没有再次调用 Glossary，也没有新的术语库版本供下游使用，说明决策内容超出了现有工作流实际落实的范围。

后续应把决定写成可核对动作，逐项记录执行节点、目标产物、版本和验收结果。动作闭环率 = 有对应执行及验收证据的动作数 / 应执行动作数；需要先把复合指令拆成明确动作才能计算。本次尚未完成这样的动作标注，不给出闭环率数值。

整体评测还需要相同原文、相同模型与规则下的单 Agent 基线，再比较质量、token、耗时和人工复核量。当前一次跑通只能报告本次完成情况，不能据此估计系统长期成功率。

## 7. 下一轮的验收安排

先独立建立全文术语标准表，再检查 88 个候选的正确去留并补充候选外漏项；翻译评价以对齐句段为单位，检查关键定义、否定、条件、数字、脚注和普通语言问题；逐条裁定 36 条审校意见，并独立查找漏报；最后对修订稿做覆盖改动范围的再次检查。

作为本项目下一轮拟采用的交付条件：严重漏译或关键含义错误须解决，未译正文和 `[待审]` 项须清零，脚注须完整，Manager 的每个执行要求须有产物与验收记录。这些是拟定的项目标准，尚未作为本轮已经通过的验收。

本轮能确认的是编排和结构校验已完成，质量诊断已找出具体缺陷，完整语义评测与验收仍待继续。

使用旧版真实译文回放新门禁时，第二块的待审标记、第三块新引入的 `accompanying` 和第四块脚注 9 缺少正文均被拦截。此回放没有调用模型，只验证已知缺陷不会再被当作可交付结果；它不证明模型已经修复这些缺陷。
